# Contributing

Node.js 24.21.0 LTS is required for this release. Run `npm ci` and `npm run verify` before a change; that command runs typecheck, tests, lint, the server build, and the VitePress docs build with link checking. Use `npm run test:coverage` when changing lifecycle or transport behavior. Tests use temporary SQLite files, an injected clock, a fake Telegram transport, and an injected HTTP fetcher; they must not require a bot token or contact Telegram. Include tests with two distinct client keys for changes to request access or idempotency, and with distinct chats and approver lists for routing changes. Add a numbered SQL migration for schema changes after a release; do not edit a migration already used by a release. Keep the core lifecycle free of Telegram and HTTP types.

Update the relevant pages in `docs/` whenever code, configuration, API behavior, examples, or recovery behavior changes. Keep the README aligned with the docs. Use `npm run docs:dev` for local editing and `npm run docs:build` before a change. The GitHub Pages workflow verifies code and docs on pull requests and publishes the docs after successful pushes to `main`. Do not include credentials, request databases, or real message contents in issues, docs, or pull requests.
